NOTE ON THE STAGE NUMBER
------------------------
Stage 6 in this project is the snapshot/restore drill
(`docs/stage-6-verification.txt`), not a teardown. Project 10 used Stage 6 for its
teardown. The teardown of this stack therefore takes the next free number, 9,
after the Stage 8 release. The content mirrors Project 10's Stage 6 record
(RESULT, numbered evidence sections, explicit limits, SIGN-OFF); only the number
differs, because this project's Stage 6 was already spent on the drill.

--------------------------------------------------------------------------------
3. DESTRUCTIVE-ACTION GATE
--------------------------------------------------------------------------------
Teardown is irreversible: it deletes the instance, its boot volume and the 200 GB
data volume that held the Qdrant collection, WAL, payloads and the Stage 6
snapshot. Order was plan → review → apply → empty state → provider check:

  $ tofu plan -destroy -out=../runtime/zero-cost-destroy.tfplan
  Plan: 0 to add, 0 to change, 8 to destroy.

No `prevent_destroy` lifecycle guard exists in `modules/storage` or
`modules/compute` for this deployment, so the data volume was eligible — the same
position Project 10's Stage 6 recorded, and the correct one for a requested
zero-cost teardown. The operator's teardown request is the approval for this
destructive action; it was scoped to this project's stack, and the reviewed plan
named exactly those 8 addresses and nothing else.

  period              2025-12-01 .. 2026-11-18

So the billable line items — the A2.Flex instance, its boot volume and the 200 GB
balanced block volume — are not only gone from the inventory, they produced no
billed cost in the window the API covers.

Limits of that figure, stated rather than glossed:
- the Usage API reports aggregated, billed cost; there is no per-hour or
  per-resource attribution behind the 0.00;
- usage and cost reports lag real time, so a handful of hours between the destroy
  and the query could hide accrual that had not yet posted;
- ALLCREDIT returned no records, so remaining trial credit is unknown (`null`),
  not zero and not full;
- the wallet records EUR 0.00 of OCI spend only; it is not a cross-cloud balance.

11. WHAT THIS RECORD DOES NOT PROVE
--------------------------------------------------------------------------------
- It is not a billing statement for any period after 2026-11-18. Zero live
  resources is an inventory fact; EUR 0.00 is a Usage API reading for the stated
  window only.
- It does not attribute cost per project. The 0.00 is tenancy-wide.
- It says nothing about AWS or GCP: those ports were never deployed, so there was
  nothing to tear down and nothing is claimed about their spend.
- It does not re-run the Stage 5 metrics. Those measurements describe a host that
  existed; this stage cannot reproduce them without a new deployment.
- It does not delete the empty `cloudguard` bucket (§6) or the terminated listing
  records. Retention of those is intentional.
- It does not verify the cloud-init template fix from Stage 5 by a fresh boot.
  That rebuild (2 add / 2 destroy) is now the natural next deployment, not part
  of this teardown.
- The pre-teardown inventory line items are taken from the state refresh and the
  Stage 5 record; no separate provider snapshot of the live host was archived
  immediately before the destroy.
