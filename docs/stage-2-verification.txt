the module had no required_providers block, so OpenTofu inferred hashicorp/oci
while the root uses oracle/oci. Each module now declares the provider source in
modules/<name>/versions.tf. Re-init and validate are clean.

5. Ingress composition (as planned)
-----------------------------------
22/tcp    from ssh_allowed_cidrs   one rule per CIDR
6333/tcp  from vector_api_cidrs    Qdrant REST
6334/tcp  from vector_api_cidrs    Qdrant gRPC
(none)    19530 documented for a Milvus-compatible port; add it to
          vector_db_ports to open it — nothing listens on it in this stack

Sources are validated at plan time: both lists reject 0.0.0.0/0 and ::/0, so a
world-open database port cannot be applied by accident. Egress is explicit
(80/tcp, 443/tcp, 53/udp) with no catch-all rule.

6. Compute and storage shape
----------------------------
instance  VM.Standard.A1.Flex, 4 OCPU / 24 GB, Ubuntu 24.04 aarch64
boot      100 GB (OS, Docker, images)
data      200 GB block volume, 10 VPUs/GB (Balanced), paravirtualized
mount     /mnt/vector-lake via ext4 label "vectorlake"
layout    /mnt/vector-lake/storage/qdrant and /mnt/vector-lake/storage/snapshots

The volume is independent of the instance lifecycle; `tofu destroy` deletes it,
which is why the storage module documents adding prevent_destroy before real
corpus data lands.

7. Portability
--------------
Root variable and output names are provider neutral; only provider.tf and the
three module bodies are OCI specific. Each file carries the mapping:

  VCN/IGW/route table/security list/subnet  -> VPC/IGW/route table/SG/subnet
                                            -> VPC network/route/firewall/subnetwork
  oci_core_instance A1.Flex                 -> aws_instance t4g.xlarge
                                            -> google_compute_instance t2a-standard-4
  oci_core_volume + attachment              -> aws_ebs_volume gp3 + attachment
                                            -> google_compute_disk pd-balanced + attached disk
  metadata.user_data (base64)               -> user_data / metadata_startup_script

State backends documented in versions.tf: OCI Object Storage (S3-compatible),
AWS S3 + DynamoDB, GCS.
