6. Evaluation loop
------------------
docker compose ... run --rm --entrypoint python ingest-worker \
  -m vlake.evaluation --dataset configs/datasets/eval_queries.jsonl --k 5

  cases         8
  k             5
  recall_at_k   0.875
  mrr           0.6458
  exit 0

These numbers belong to the offline hashing embedder, which captures lexical
overlap only and is not a semantic retriever. The exact-lexical queries
("safe repeated ingestion without duplicate points", "embedding dimension
storage cost") score 1.0, while paraphrase queries lose the top rank. This is
the expected behaviour of the fallback provider and the reason the evaluation
hook exists; no semantic-quality claim is made for Stage 1.

7. Defects found and fixed during verification
----------------------------------------------
- config.Settings/CollectionConfig used dataclasses with slots=True while
  reading class-level defaults, which are member descriptors under slots. Any
  execution without a fully populated environment raised AttributeError.
  Defaults are now read from an instance, and a regression test asserts that
  Settings.from_env() works with an empty environment.
- qdrant-client/server minor mismatch (described in section 2).
- Git Bash converted a container path (/app/configs/...) into a Windows path,
  so the evaluation CLI now takes the working-directory-relative path; the
  README documents the relative form.
- Host port 8080 conflicted with the CloudGuard dev server; the project default
  moved to 8085.

- The sentence-transformers provider was not executed (model download and
  CPU inference belong to the live stage).
- No performance, concurrency or memory benchmark; no latency claim beyond the
  single local request above.
- Snapshot/restore is configured and mounted but has not been drilled.
- Qdrant logs a warning that an API key is used over plain HTTP. The connection
  is container-to-container on a private bridge network; TLS termination is a
  Stage 3/4 item.
